          Until reconnected, the deployed frontend at inik-cafe.vercel.app
          does not reflect any changes merged to inik-cafe main, and vercel.json
          rewrite is not active → /api/chat calls will 404 in production.
          Severity: HIGH (blocks all frontend QA)

  RISK-2  Release tags not on remote
          v1.5.0-backend and v1.5.0-frontend exist as local annotated tags only.
          The environment proxy blocks git push for tag refs (403).
          Severity: LOW (cosmetic — code is correct on main)

  RISK-3  sendWithAgent() does not read d.agent_mode from response
          The one-shot "Talk to Rick Royce →" handoff path does not update
          activeMode from the backend response. If backend returns agent_mode
          different from 'rick_royce' on the first Rick response, the UI state
          would be inconsistent. In practice this does not happen (explicit
          requested_mode='rick_royce' always returns agent_mode='rick_royce').
          Severity: LOW

  RISK-4  README curl example shows "agent_mode": "auto"
          Line 417 of README.md uses "auto" in a curl example.
          After V3 restore, "auto" is not a named mode and will not save
          a preference. Not a runtime bug but misleading documentation.
          Severity: LOW

  RISK-5  test_v3_contract_restore.py blocked in CI pytest venv
          The pytest venv lacks pydantic. 15 logic tests run fine under
          the application's Python environment but would fail in a bare pytest
          run without installing project dependencies first.
          Severity: LOW (logic verified via direct python3 -c checks)
